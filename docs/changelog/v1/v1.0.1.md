# @cldmv/uuid v1.0.1 Changelog

**Release Date**: December 2025
**Release Type**: Patch
**Branch**: `master`

---

## Overview

v1.0.1 corrects how the Timestamp Variants store and read back their signed 70-bit timestamps, so a timestamp now round-trips exactly, including dates before 1970. It also adds a demo script and reworks the README around the extended specification.

Commit: [`efd1f6c`](https://github.com/CLDMV/uuid/commit/efd1f6c)

---

## 🐛 Bug Fixes

### Timestamp encoding and extraction

- `getTimestamp()` now extracts the signed 70-bit timestamp correctly.
- Negative (pre-epoch) timestamps use the ordering rule `stored = (2^69 − 1) − |magnitude|`, so they sort correctly before positive ones.
- `TA` uses **seconds** precision and `TB` uses **milliseconds** precision. Before this fix, `TA` used milliseconds.
- The timestamp field is written after entropy is applied, so entropy no longer overwrites it while the UUID is being built.

### Issuer accessors on Timestamp Variants

- `getIssuerID()` and `getIssuerCategory()` return `null` for Timestamp Variants instead of reading timestamp bits as an issuer.

## ✨ Features

- **Demo script**: `npm run demo` (`scripts/demo-custom-uuids.mjs`) generates TA, TB and IA UUIDs, then extracts and verifies their data. The output is readable and includes pre-1970 examples.

## 📚 Documentation

- The README now centres on the extended specification, with formal bit-layout diagrams, the issuer ID allocation ranges and examples for every variant.

## 🔧 CI & tooling

- Added negative-timestamp and ultra-short-variant tests. The suite now has 170 tests, with exact timestamp round-trip checks.

---

## Upgrade notes

- No API changes. **`TA` values change meaning.** v1.0.0 wrote milliseconds into `TA`, and this release writes and reads seconds. Timestamp Variant UUIDs generated with v1.0.0 may not decode to the same instant under v1.0.1.
