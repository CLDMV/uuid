## Overview

v1.1.6 is a small follow-up to the v1.1.5 devcheck fix: it tightens argument scanning and softens the warning text.

> **Not published to npm.** Like v1.1.3, this version exists only as a [GitHub Release](https://github.com/CLDMV/uuid/releases/tag/v1.1.6). v1.1.7 is the next version on npm, and it includes these changes.

---

## 🐛 Bug Fixes

### devcheck scanner advances past a consumed `--conditions` value ([#13](https://github.com/CLDMV/uuid/pull/13), release [#14](https://github.com/CLDMV/uuid/pull/14))

In the space-separated forms (`--conditions x`, `-C x`), the scanner read the next token as the value but didn't skip over it, so a value that looked like a flag could be processed twice. The scanner now skips the consumed token. It also drops the `-C=value` branch, because Node rejects that form outright. The valid forms are `--conditions=x`, `--conditions x` and `-C x`. Added `-C` test coverage.

### Softer devcheck message ([#15](https://github.com/CLDMV/uuid/pull/15))

The warning no longer claims the package "is loading from dist/", which isn't true when devcheck runs standalone or in an unbuilt checkout. It now describes the default resolution: imports resolve to `dist/` by default, or fail if it isn't built.
