# @cldmv/uuid v1.1.0 Changelog

**Release Date**: December 2025
**Release Type**: Minor
**Branch**: `master`

---

## Overview

v1.1.0 adds RFC 9562 version 8 UUIDs and one `version()` call that works for both RFC and custom variants. Internally, each UUID version now lives in its own module.

Commit: [`f9c6285`](https://github.com/CLDMV/uuid/commit/f9c6285)

---

## ✨ Features

- **RFC 9562 v8** (custom / experimental) UUID generation.
- **`UUID.version(uuid)`** (static) and **`instance.version()`**: one version check for every UUID. They return `1`–`8` for RFC UUIDs and `TA` / `TB` / `IA` for the custom variants.

## ♻️ Refactoring

- The RFC generators moved out of the single `src/lib/rfc-uuids.mjs` into `src/lib/versions/rfc/` (`v1`, `v35`, `v4`, `v6`, `v7`, `v8`). The custom variants moved into `src/lib/versions/timestamp/` and `src/lib/versions/issuer/`.
- The shared UUID constants moved into `src/lib/constants.mjs`.

## ⚠️ Deprecations

- `getVariantIdentifier()` and `detectVariant()` are deprecated in favour of `version()`. They still work in this release.

## 📚 Documentation

- The README documents v8, `UUID.version()` and `instance.version()`.

---

## Upgrade notes

- No breaking changes to the public API. Replace `getVariantIdentifier()` / `detectVariant()` calls with `version()`.
- **Known issue:** this release removed `types/index.d.mts` while `package.json` `"types"` still pointed at it, so TypeScript consumers got no declarations for the root entry. The file was restored in [v1.1.2](./v1.1.2.md).
