# @cldmv/uuid v1.1.7 Changelog

**Release Date**: August 2026
**Release Type**: Patch
**Branch**: `release/1.1.7`

---

## Overview

v1.1.7 exposes `./package.json` through the `exports` map, so tools can resolve the package manifest by name.

This is the first npm release since v1.1.2. It carries the unpublished changes from v1.1.3–v1.1.6: the v4 release flow, the devcheck fixes and the removal of the dead `./devcheck` export. See those changelogs for details.

---

## 🐛 Bug Fixes

### Expose `./package.json` in the exports map ([#17](https://github.com/CLDMV/uuid/pull/17), release [#18](https://github.com/CLDMV/uuid/pull/18), fixes [#6](https://github.com/CLDMV/uuid/issues/6))

Node's `exports` map is a strict allowlist. With only `.` and `./main` declared, `require.resolve("@cldmv/uuid/package.json")` threw `ERR_PACKAGE_PATH_NOT_EXPORTED`, which broke tools that locate a package through its manifest (including the `@cldmv/rummage` web build). The conventional `"./package.json": "./package.json"` entry is now present. A regression test checks both the exports entry and real Node self-resolution.

## Upgrade notes

- No breaking changes. If you're upgrading from v1.1.2 on npm, note that the `@cldmv/uuid/devcheck` subpath was removed in v1.1.5. It never resolved to a shipped file.
