# `@cldmv/uuid` v1.3.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.3.2`

---

## Overview

v1.3.2 is a development-tooling release. The test config now resolves the package through the `uuid-dev` export condition the way it was meant to, and CI type-checks the declarations with `types:check` instead of skipping the step.

No library code changed. The `UUID` API, the generated UUIDs and the published files are the same as in v1.3.1, and nothing changes for anyone installing the package.

---

## 🔧 CI & tooling

### Tests run against `src/` through `devCondition()` ([#91](https://github.com/CLDMV/uuid/pull/91))

`.configs/vitest.config.mjs` set `test.nodeOptions` to pass `--conditions=uuid-dev` to the test workers, but vitest has no such option, so the condition never reached them. The config now builds on `devCondition()` from `@cldmv/configs` (bumped to `^1.4.0`), which sets the resolver conditions and the worker `execArgv`, so Node's own resolver picks `src/` through the `uuid-dev` export condition too.

### CI runs `types:check` ([#93](https://github.com/CLDMV/uuid/pull/93))

- The CI type-check step runs `npm run types:check` (`tsc --noEmit` on `.configs/tsconfig.dts.jsonc`, which validates the hand-written `.d.mts` declarations) and is no longer skipped. `checkJs` stays off, so the JavaScript source itself isn't type-checked.
- `test:types`, the consumer-side test of the built types, stays part of `npm test`.
- The unused `build:types` script is gone; `types:build` already replaced it in `build:ci`.
