# @cldmv/uuid v1.2.3 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `release/1.2.3`

---

## Overview

v1.2.3 changes only maintenance and release tooling. **No runtime code changed.** The files that ship (`index.mjs`, `index.cjs`, `dist/`, `types/`) are the same as in v1.2.2, so UUID generation, parsing and the public API behave exactly as before.

The release updates the repository's CI and release workflows to the current `CLDMV/.github` v4 templates, adds a bundle-size check that tracks the published entry files, and brings in two dev-only dependency bumps.

---

## 🔧 CI & tooling

### Sync the v4 workflows with the CLDMV/.github v4.29.2 templates ([#37](https://github.com/CLDMV/uuid/pull/37))

Every workflow caller under `.github/workflows/` now matches the v4.29.2 templates. New workflows:

- **`release-merge.yml`**: squash-merges the persistent `next → master` release PR through the REST merge API once it's approved, using the PR body as the commit message. That way the curated release notes always become the release commit and the GitHub Release body.
- **`member-auto-merge.yml`**: turns on auto-merge for org-member PRs into `next` / `hotfixes` that use the standard branch prefixes.
- **`dependabot-recreate.yml`**: runs `@dependabot recreate` automatically when a Dependabot PR gets stuck after someone other than Dependabot edits it.
- **`provenance.yml`**: generates SLSA build provenance for published releases. It runs separately from the publish workflow, so a provenance failure can't block a publish.
- **`pr-notify.yml`**: sends one notification each time a PR opens.

The existing callers (`ci.yml`, `publish.yml`, `codeql.yml`, `update-major-version-tags.yml`, `master-commit-audit.yml`, and others) and `.github/dependabot.yml` were refreshed to match the same template version.

### Add the bundle-size workflow ([#38](https://github.com/CLDMV/uuid/pull/38))

A new `bundle-size.yml` builds the package with `npm run build:ci` and reports how the published files change in size on each PR. It measures the top-level `index.mjs` / `index.cjs` entry points plus everything under `dist/`, which is the same set of files npm ships. The same PR adds `📊 Bundle Size` back to `release-merge.yml`'s `workflow_run` trigger list, matching the template. The release-merge gate waits for every check on the release PR, so it also needs to re-evaluate when this new check finishes.
