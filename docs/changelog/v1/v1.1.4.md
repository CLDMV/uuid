# @cldmv/uuid v1.1.4 Changelog

**Release Date**: August 2026
**Release Type**: Patch
**Branch**: `release/1.1.4`

## Overview

v1.1.4 is a CI-only fix: release-relevant CI runs are no longer cancelled by newer runs, so the release PR always posts a green check. No runtime code changed.

> **Not published to npm or tagged.** v1.1.4 exists only as a release commit on `master` ([`956b6ee`](https://github.com/CLDMV/uuid/commit/956b6ee)). Its changes first reached npm in v1.1.7.

---

## 🔧 CI & tooling

### Never supersede release-relevant CI runs ([#4](https://github.com/CLDMV/uuid/pull/4), release [#5](https://github.com/CLDMV/uuid/pull/5))

The CI concurrency group now derives the release base branch the same way `resolve-release-base` does: from the `CLDMV_RELEASE_BASE` variable, falling back to the repo's default branch. Before, `refs/heads/master` / `main` were hardcoded. `next` and `hotfixes` stay literal, since they're the flow's fixed integration branches. This mirrors the `CLDMV/.github` core-cicd `ci.yml` template.
