# `@cldmv/uuid` v1.3.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/1.3.0`

---

## Overview

v1.3.0 moves the package to a built layout: the code lives in `src/`, tsup bundles it into `dist/`, and the published package ships `dist/`, `types/` and `typings/` instead of root `index.mjs` / `index.cjs` files and a raw copy of the source. The `UUID` API, the generated UUIDs and the import paths consumers use (`@cldmv/uuid`, `@cldmv/uuid/rng`, `@cldmv/uuid/bytes`, `@cldmv/uuid/hash`) are unchanged. `@cldmv/uuid/main` still works but is now a deprecated alias of the package root.

**The Node.js floor goes up from 16.12.0 to 22.22.0.** See [Requirements](#-requirements) and the upgrade notes before upgrading.

---

## ✨ Features

### Built from `src/` with tsup ([#80](https://github.com/CLDMV/uuid/pull/80), closes [#78](https://github.com/CLDMV/uuid/issues/78))

- **Entry files.** The ES module entry is `src/index.mjs` and the CommonJS entry is its sibling `src/index.cjs`. tsup bundles `src/index.mjs` into a minified `dist/index.mjs` (function and class names kept) and copies `src/index.cjs` verbatim to `dist/index.cjs`, a few lines that `require()` the sibling `index.mjs`. `require("@cldmv/uuid")` still returns the `UUID` class with `UUID`, `uuid` and `ISSUER_CATEGORIES` on it, and the CommonJS and ES module entries return the same objects.
- **Subpaths.** `./rng`, `./bytes` and `./hash` are built as their own files in `dist/lib/`, Node and browser variants both, and the main bundle imports them through the package's exports map. A bundler therefore still picks the `browser` variant instead of getting the Node one baked into `dist/index.mjs`.
- **Issuer data is bundled.** The issuer registry imports `data/issuers.json` statically instead of reading it from disk with `fs` relative to its own path, so the data is inlined into the bundle. The registry no longer imports `fs`, `path` or `url`, and the `Could not load issuers.json` warning for a missing file is gone because the file can no longer be missing.
- **Types.** Declarations come from `types/src/`. `@cldmv/uuid/main` now has the same types as the root.
- **`sideEffects`.** The package is still side-effect free except for the `./main` alias, which prints its deprecation warning on import; `sideEffects` lists that file.

### `@cldmv/uuid/main` is a deprecated alias ([#80](https://github.com/CLDMV/uuid/pull/80))

`@cldmv/uuid/main` used to point at its own copy of the UUID module. It now re-exports the package root, so every value is the same object `@cldmv/uuid` exports, and it gains the default export the root has. Importing it prints a `DeprecationWarning` once per process with code `CLDMV_UUID_MAIN` (`console.warn` where there is no `process`). `node --no-deprecation` silences it. The alias is removed in the next major version; import `@cldmv/uuid` instead.

### `uuid-dev` export condition on the root ([#80](https://github.com/CLDMV/uuid/pull/80))

The `uuid-dev` condition, which before only covered the subpaths, now sits on `.` too, for `import`, `require` and `types`. In a checkout the package resolves to the built `dist/` by default and to `src/` under `--conditions=uuid-dev`. The test suites run against `src/` through it. Installed copies never see the condition.

## 📦 Requirements

### Node.js 22.22.0 or later ([#79](https://github.com/CLDMV/uuid/pull/79), [#80](https://github.com/CLDMV/uuid/pull/80))

`engines.node` is `>=22.22.0`, for `import` and `require()` alike. v1.2.6 declared `>=16.12.0` for `import`, and its README said `require()` needed `^20.19.0 || >=22.12.0`. [#79](https://github.com/CLDMV/uuid/pull/79) first raised the floor to `^20.19.0 || >=22.13.0`, and [#80](https://github.com/CLDMV/uuid/pull/80) raised it again to 22.22.0 because the development toolchain (tsup 9 among others) doesn't run on earlier 22.x releases, so they can't be tested. The `require()` error message on a Node.js without `require(esm)` and the CI matrix floor say 22.22.0 too.

On Node.js 16 through 22.21, installs now report `EBADENGINE` (or fail under `engine-strict`), and those versions are no longer tested.

## 🐛 Bug Fixes

### Development check removed ([#79](https://github.com/CLDMV/uuid/pull/79))

The root `devcheck.mjs`, which the entry tried to load in a source checkout, is gone along with its test. It was never published, so installed copies are unaffected. The `uuid-dev` condition already chooses `src/` or `dist/` in a checkout.

## 🔧 CI & tooling

- `build:ci` runs lint and format checks when present, then `types:build` and the tsup `build`; the coverage jobs run it before measuring (`coverage_build_command`) ([#80](https://github.com/CLDMV/uuid/pull/80)).
- `test:cjs` and `test:types` build first, and the CommonJS tests cover both `dist/` and `src/` entries. A new test covers the `./main` alias and its warning ([#80](https://github.com/CLDMV/uuid/pull/80)).
- The bundle-size check measures `dist/**.mjs` and `dist/**.cjs` ([#80](https://github.com/CLDMV/uuid/pull/80)).
- The CI matrix floor is 22.22.0 (was 22.12.0) ([#80](https://github.com/CLDMV/uuid/pull/80)).
- `prepack` runs the build, so a packed or published tarball always carries a fresh `dist/`.

## Upgrade notes

- **Node.js 22.22.0 or later is required** (was 16.12.0 for `import`, and `^20.19.0 || >=22.12.0` for `require()`). Upgrade Node.js first, or stay on v1.2.6.
- Replace `@cldmv/uuid/main` with `@cldmv/uuid`. It still works in 1.x but prints a `DeprecationWarning` (code `CLDMV_UUID_MAIN`) and goes away in the next major version.
- Nothing else changes for consumers: the `UUID` API, its output, and the `@cldmv/uuid`, `./rng`, `./bytes` and `./hash` import paths are the same. Code that reached into the package's file layout (root `index.mjs`, `dist/uuid.mjs`, `types/dist/`) outside the exports map has to move to the exported paths.
