# @cldmv/uuid v1.1.5 Changelog

**Release Date**: August 2026
**Release Type**: Patch
**Branch**: `release/1.1.5`

---

## Overview

v1.1.5 fixes the development-mode guard (`devcheck`), which warns when a source checkout runs from `dist/` instead of `src/`. It also removes a broken `./devcheck` subpath export and corrects the `@Project` header across the repo.

> **Not published to npm.** Like v1.1.3, this version exists only as a [GitHub Release](https://github.com/CLDMV/uuid/releases/tag/v1.1.5). v1.1.7 is the next version on npm, and it includes these changes.

---

## 🐛 Bug Fixes

### devcheck: condition-only trigger, `execArgv` detection, scoped-install guard ([#10](https://github.com/CLDMV/uuid/pull/10), fixes [#9](https://github.com/CLDMV/uuid/issues/9))

- **Trigger is now condition-only.** Only `--conditions=uuid-dev` selects `src/`, and `NODE_ENV` has no effect on resolution. The old check was wrong in both directions. `NODE_ENV=development` without the condition stayed silent while actually running from `dist/`. Setting the condition without `NODE_ENV` warned even though resolution was correctly on `src/`.
- **Detects the condition in `process.execArgv`** as well as `NODE_OPTIONS`. That covers `node --conditions=uuid-dev file.mjs` and vitest workers, which pass the flag in `execArgv`.
- **Matches `--conditions` values exactly.** Each occurrence is one literal condition, so values are not split on `,` or `|` (Node doesn't split them either). Substrings such as `not-uuid-dev` no longer count as a match.
- **Skips when installed as a dependency**, including the scoped `node_modules/@cldmv/uuid` layout, so a git or tarball install never exits inside a consumer's app.

### Remove the dead `./devcheck` export

The `./devcheck` subpath pointed at `devcheck.mjs`, which is not in the published `files` allowlist, so `import "@cldmv/uuid/devcheck"` failed for every consumer. devcheck is an internal guard that `index.mjs` loads with a relative import, so the export was removed.

## 🔧 CI & tooling

- **Header `@Project` corrected** repo-wide from the leftover `@cldmv/slothlet` template value to `@cldmv/uuid`. `tools/fix-headers.mjs` now carries the right project name, so `npm run fix:headers` stops re-stamping the wrong value. A duplicate header in `.configs/tsconfig.dts.jsonc` was also removed.
- New `tests/DevCheck.test.vitest.mjs` covers the devcheck matrix.
