# @cldmv/uuid v1.2.0 Changelog

**Release Date**: August 2026
**Release Type**: Minor
**Branch**: `release/1.2.0`

---

## Overview

v1.2.0 makes UUID generation work in browser bundles. The package no longer imports any Node built-ins on its browser path. Node keeps its native `crypto` / `Buffer` fast paths, and browsers get Web Crypto and pure-JS equivalents, chosen automatically through the `browser` export condition.

---

## ✨ Features

### Zero-node-builtin UUID generation for browser bundlers ([#23](https://github.com/CLDMV/uuid/pull/23), release [#20](https://github.com/CLDMV/uuid/pull/20), fixes [#21](https://github.com/CLDMV/uuid/issues/21))

Before this release, the static `import crypto from "crypto"` in `uuid.mjs` and in every RFC / timestamp version file made the package impossible to bundle for browser targets: esbuild with `platform: "browser"` couldn't resolve `crypto`. Even past that, the internal `Buffer`-based representation threw a `ReferenceError` at runtime.

- Random bytes, hex / byte handling and hashing are split into isomorphic node + browser module pairs, published as the new subpaths **`./rng`**, **`./bytes`** and **`./hash`**. The package's `browser` export condition selects the right variant, and the package imports these subpaths through their own names.
- The browser variants use `globalThis.crypto.getRandomValues` and pure-JS MD5 / SHA-1. `crypto.subtle` is async, and using it would have broken the synchronous v3 / v5 API.
- The internal UUID byte store moved from `Buffer` to plain `Uint8Array`, so the same code runs in both environments.
- Checked against the RFC 1321 (MD5) and FIPS 180-1 (SHA-1) test vectors, cross-checked with `node:crypto`, and run in headless Chromium: no `Buffer` / `node:crypto` references, and correct output including the standard v3 / v5 DNS-namespace vectors.

## 🔧 Dependencies

## Upgrade notes

- No breaking changes to the public API. Values are identical and generators stay synchronous.
- The internal `_buffer` field is now a `Uint8Array` rather than a Node `Buffer`. `toBuffer()` still returns a `Buffer` on Node, and a `Uint8Array` copy in the browser.
