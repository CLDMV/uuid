# `@cldmv/uuid` v2.1.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/2.1.0`

---

## Overview

v2.1.0 publishes the entropy helpers as `@cldmv/uuid/entropy` and adds `sha256` to `@cldmv/uuid/hash`.

`EntropySource` has been in the repository since the first release but was never reachable from the package. It is now its own subpath, kept out of the main bundle, and runs in browsers as well as Node. Before going public, its bit-balance check was reworked so it scales with input length, and one method name was corrected.

Nothing in the main entry changed: TA, TB, IA and RFC ids, their timestamps and every existing export behave as in v2.0.1.

## ✨ Features

### `@cldmv/uuid/entropy` ([#136](https://github.com/CLDMV/uuid/pull/136), resolves [#135](https://github.com/CLDMV/uuid/issues/135))

```javascript
import { EntropySource } from "@cldmv/uuid/entropy";

EntropySource.calculateRequiredEntropy(1e-9, 1_000_000); // => 69 random bits for a one-in-a-billion collision chance
const bytes = EntropySource.generateSecureBytes(16);
EntropySource.validateEntropyQuality(bytes).passed; // => true for a healthy source
```

`EntropySource` is a set of static helpers:

- `generateSecureBytes(byteCount)` and `generateEntropy(bits)`: random bytes from the platform CSPRNG.
- `calculateRequiredEntropy(probability, count)`: the birthday-bound number of random bits that keeps the collision chance across `count` ids at or below `probability`.
- `validateEntropyQuality(bytes)` and `generateValidatedEntropy(byteCount, [maxAttempts])`: sanity checks for a broken or stuck source (all zeros, all ones, bit balance, long runs), and a generator that retries until a draw passes.
- `mixEntropySources(sources)`: XOR of several byte arrays.
- `createTimestampIndependentEntropy(timestamp, [additionalBytes])`: SHA-256 of a timestamp plus fresh random bytes.
- `estimateShannonEntropy(bytes)` and `analyzeEntropySource(generator, [sampleCount])`: frequency-based entropy estimate, and repeated-output and timing warnings for a generator.

Every method works on `Uint8Array` and returns `Uint8Array` (Node `Buffer`s work as inputs). Bytes come from `@cldmv/uuid/rng`, hex from `@cldmv/uuid/bytes` and SHA-256 from `@cldmv/uuid/hash`, so one build serves Node and browsers. Changes made while preparing it for release:

- **Bit balance scales with length.** The check used a fixed 40-60% window for the share of set bits. That rejected about 2.7% of good 16-byte draws and was far too loose for large inputs. It now allows 4 standard deviations either side of half, so a fair source fails about once in 16,000 checks at any length. The result reports the window as `min` and `max`.
- **`estimateShannnonEntropy` is `estimateShannonEntropy`.** The old spelling was never published.

### `sha256` in `@cldmv/uuid/hash` ([#136](https://github.com/CLDMV/uuid/pull/136))

`sha256(bytes)` returns the 32-byte digest. The Node build uses `node:crypto`; the browser build is a synchronous pure-JS implementation, tested against the FIPS 180-4 vectors and `node:crypto` across block-boundary lengths.

## 🐛 Bug Fixes

### Flaky `generateValidatedEntropy` test ([#134](https://github.com/CLDMV/uuid/pull/134), fixes [#133](https://github.com/CLDMV/uuid/issues/133))

The test ran the validator on real random bytes with two attempts, so about one run in 1,400 failed although nothing was wrong. It now uses fixed bytes, and a second test covers the retry path.
